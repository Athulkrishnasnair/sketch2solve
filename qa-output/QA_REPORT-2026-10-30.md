# Sketch2Solve QA report

**Run date:** 2026-10-30  
**Scope:** Independent review of the pending-review geometry editor fix and strongest available API/frontend/browser verification.

## Findings

- The parent detail view mounts `GeometryReview` for saved sketch proposals. The editor opens through `GET /api/analyses/<id>/draft` regardless of `pending_review`; the pending AI proposal remains separately stored and labeled proposal-only.
- The editor entry control is enabled outside the draft-load request. Draft saving calls only the draft API, requires the coordinate attestation, and reports that the result is still unapproved. `POST /review` is a separate explicit action; the solve action is exposed only for `review_status === "reviewed"`.
- Backend routes validate draft schema and coordinate attestation on save, revalidate on review and solve, and return `REVIEW_REQUIRED` unless the saved draft was explicitly reviewed. Solver failure stores diagnostics and retains the reviewed draft. Existing backend tests cover these boundaries.
- The browser assertion that the pending editor is enabled does not by itself detect restoration of the old generic `:disabled="busy"` binding while `busy` starts empty. Added a dependency-free Node contract test that checks the loading-only template condition directly; it fails if the generic binding is restored.
- No live AI call or system package installation was made. No backend product code, credentials, or MCP configuration changed.

## Workflow verification boundary

The UI E2E spec covers upload → edit → save → review → solve using a deterministic mocked provider, and the frontend contract tests guard key UI workflow rules. **The complete workflow was not verified in a real browser** because Chromium could not load its missing libraries.
